sndstation documentation

sndstation turns small Linux handhelds into music machines. Shops sell these units as cheap game consoles, and many end up in a drawer. Each one holds a capable ARM computer. sndstation is the ecosystem that puts it to work for musicians: an OS image, or a package for a Debian system a unit already runs, with a launcher, an SDK, plugins, and updates. David Viens at Plogue started the project in 2026.

Status: private beta. No unit has passed its checks, no image is public, and the API is 0.x. This repository is private until the docs are ready.

Two places for docs

  • This repository holds the guides, sorted by who reads them: users, developers, and people who build with coding assistants. Most are stubs today. Each stub says what it will cover and where to look until then.
  • sndstation/sndstation holds the reference that sits next to the code: the SDK, the launcher, and each subsystem. This repository links to those pages and does not copy them.

For users

  1. Find a supported unit. sndstation runs on RK3326, RK3566, H700, and A133P handhelds. A shop listing names the model, not the chip: supported hardware lists the models, and Identifying your unit says how to tell which one you hold. On an RK3326 unit, read it before you flash. To choose one to buy, the device guide lists the units we have validated and ranks the rest on paper.
  2. Get a microSD card of your own. Do not flash the card the unit came with. Put it aside as it is: it boots the stock firmware, so it shows whether a fault is in the hardware or in what you flashed. For which card to buy, and how to check it for a fake, we defer to Handheld Index's guide to SD cards.
  3. Flash the image for your unit with balenaEtcher: pick the image, pick the card, flash. For the writing itself we defer to balena's instructions and support. Which image a unit takes is in Getting an image. During the private beta no image is public.

An image is not the only way in. The platform also installs as a .deb onto an equivalent "Lite" Debian trixie system: the stock Raspberry Pi OS Lite images and Armbian are that. Switchroot's L4T-based Linux for the Switch is on Ubuntu 24.04, which is close enough. See Installing on a handheld. 4. Put the card in and switch on. The unit boots to the launcher. Set up the network in SETTINGS → Network: Wi-Fi where the unit has it, or USB networking to a computer where it does not. 5. Make music. The user guide is a stub; until it is written, the launcher describes every screen. Before buying anything to plug in, Peripherals says what works on your unit: interfaces and MIDI, controllers, drives, Wi-Fi dongles, webcams.

For developers

A CLAP plugin built for Linux arm64 against Debian trixie's glibc loads on a unit as it is. The launcher finds it, checks it, and rates it (CLAP plugins). To go further, pick a route:

  • Write an app. Writing an app takes examples/hello from a copy on your computer to a unit's launcher. The quickstart is the short version, and the headers are in the API reference.
  • Give a plugin the unit's panel and controls. embedded-hardware.md describes the host side of the clap.embedded-hardware extension. A plugin that uses it does not depend on sndstation's code.
  • Publish packages. Publishing a vendor source.

Guides:

Building on a Linux desktop, on macOS, and on a handheld is in Installation.

For people who build with coding assistants

sndstation does nothing special for coding assistants. An app written with one uses the same SDK, the same docs, and the same units as any other.

We use these tools ourselves. What we do with their output is question it, and hold it to the standard of any developer on the team: a person reads every line, runs it, and measures it on a unit.

  • Shipping an app with a coding assistant, a stub.
  • AGENTS.md is what an assistant reads before it works in the sndstation repository.
  • A change you send to sndstation itself follows the AI use policy: you are its editor.

Writing a page

Docs are in American English and follow the rules in sndstation's AI_POLICY.md and .vale.ini: plain sentences, no filler, and facts someone measured. Start a how-to from the guide template. A stub keeps its Stub note until the page is written.
