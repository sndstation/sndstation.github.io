Known issues

Each item gives the symptom, what it affects, a workaround where there is one, and the issue that tracks it. Per-unit status is in supported.md.

For developers

A pull request gets no CI run until someone asks for one

  • Symptom: a pull request shows no build or test run.
  • Why: CI runs nothing on its own: the account has a small allowance of Actions minutes for this private repository, and macOS bills at 10×.
  • Workaround: add the label ci: build, ci: linux, ci: macos, or ci: aarch64 to the pull request, or use Run workflow under Actions (CONTRIBUTING).

The five tests that used to fail on macOS (test_socid, test_about, test_audioin, test_mdfourier and test_audioout) pass there since #181. On macOS, test_mdfourier reports a 192 kHz difference rather than failing, because the reference checksums come from glibc's math library. Measured on an Apple-silicon Mac (macOS 27.3): 40 of 40 tests pass.

On the units

RG40XX H and RG35XX SP: no button map of their own

  • Symptom: neither unit has a map made for it. Both share the speculative RG28xx (more?) entry in config/gamepads.json.
  • RG35XX SP: that entry works. On two SP units the launcher matched it to the common17 map (17 buttons), measured 2026-11-16 (#132).
  • RG40XX H: not tried yet. If it does not match, the unit may not get past the first screen.
  • Affects: Anbernic RG40XX H (#130), Anbernic RG35XX SP (#132).
  • Workaround: none recorded for the RG40XX H. Nobody has tried Map this controller, the wizard at SETTINGS → Controls, on it (launcher.md, Controls). A unit with no pad found at all leaves to a shell after five seconds, where a keyboard or ssh works (launcher.md, "No gamepad at all"); that is a way in, not a fix.
  • Tracking: #130 and #132. Both are marked as needed before the developer beta.

RGB30 and TRIMUI Smart Pro: no routes for the built-in card

  • Symptom: there is no codec table for the built-in card, so sound is not routed as on the other units. On the RGB30 there is a card choice (the built-in card is taken over HDMI's card 0) but no routes. For the A133P there is nothing.
  • Affects: Powkiddy RGB30 (#129), TRIMUI Smart Pro (#131).
  • Workaround: none recorded. Give these two units to testers, not to someone who needs sound to build an app. A USB audio interface is picked automatically when plugged in (launcher.md, Audio), but that has not been tried on these two units.
  • Tracking: #129 and #131.

RGB30: realtime audio refused under CONFIG_RT_GROUP_SCHED

  • Symptom: the audio thread stays an ordinary thread, and stderr says the kernel is refusing SCHED_FIFO although ulimit -r allows it.
  • Affects: kernels built with CONFIG_RT_GROUP_SCHED, found on the RGB30 (kernel 7.0.2).
  • Workaround: boot with rt_group_sched=0 on the kernel command line. The install script checks for this kernel and says so, but does not change the boot line (rt-bench.md, "Allowing it").
  • Tracking: #129 ("reproduces or is closed").

RG35XX SP: the lid file ships empty

  • Symptom: config/deviceevents.json has no entry for the SP, so on a stock BSP image the lid's hallkey attribute is never read.
  • Affects: the RG35XX SP on the stock BSP image. On the sndstation rootfs the lid is evdev gpio-keys-lid and needs no entry (device-events.md).
  • Workaround: use the sndstation rootfs. To add the entry, read the attribute with the lid open and shut and report it (reporting.md).
  • Tracking: #132.

RG35XX SP: no Bluetooth on about half of boots

  • Symptom: no hci0 appears, so bluetoothd never starts and paired controllers stay away. The Realtek RTL8821CS on the SP's UART never answers the link's SYNC, and the driver logs nothing more.
  • Affects: the RG35XX SP. Measured on an SP (Debian 13, kernel 7.2): 4 boots of 8.
  • Workaround: none needed with the package installed. Its handheld half enables sndstation-bt-h5.service. At boot it rebinds the driver when no hci device appears within six seconds, up to three times. Measured on an SP with the service installed: 6 reboots in a row, hci0 and a paired BLE-MIDI controller back every time, one of them by a rebind (6be33dc). What it did is in journalctl -u sndstation-bt-h5. The same rebind by hand is two commands run as root (launcher.md, "Bluetooth at boot").
  • Tracking: none needed, because the boot service is the fix. The SP's slot is #132.

H700: SDL's ALSA stream panics the kernel under PREEMPT_RT

  • Symptom: a kernel panic in sun6i_dma_interrupt, racing a stop of the card's DMA. It follows SDL's ALSA stream, which starts with one frame queued and so underruns, and restarts, at a short period (audio-device.md, §3.0).
  • Affects: H700 units (RG40XX H, RG35XX SP, RG CubeXX) on a PREEMPT_RT kernel.
  • Workaround: none needed by default. sndstation plays through its own stream on alsa-lib, which fills the buffer before it starts. Setting SNDSTATION_AUDIO_STREAM=sdl (or sndstation-audiotest --sdl) brings SDL's stream back for comparison. Do not set it on an H700 under PREEMPT_RT unless you accept a panic. A program that does not go through the SDK uses SDL's stream and is exposed.
  • Tracking: #130 ("SDL's ALSA stream stays off this card").
