USB networking

Part of the sndstation design. Built and shipping: tools/sndstation-netctl (usb-* commands), the launcher's SETTINGS → Network → USB networking page (launcher/settings.cpp, launcher/netctl.cpp), and system/sndstation-usbnet.service. The page's own behavior is in launcher.md; this is how the whole thing works.

What it is for

A network over a USB cable, with no Wi-Fi: a unit and the computer it is plugged into, or several units on one USB hub. On a hub, one unit is the host and the others plug into it, directly or through the hub. Units on it reach each other at fixed or handed-out addresses, so an app on one can talk to an app on another (ssh, a game's TCP connection, anything IP).

The three modes

Mode The unit is Its address Hands out addresses
Connected to my PC a USB Ethernet device 10.55.0.1 to the computer
Connected to a hub a USB Ethernet device from the host, 10.56.0.x no, it asks
As a host a USB host with a bridge 10.56.0.1 10.56.0.10–254

Picking a mode turns off whichever was on first. Every unit starts off after a power-on unless Remember network settings is on.

No mode hands out a route or DNS. Each one reaches the others; nobody's own traffic goes through a unit. A wired default route outranks Wi-Fi, so one handed out here would quietly take over a laptop's internet. Hub mode refuses a route and DNS from whatever answers it, for the same reason.

Connected to my PC

The port becomes a USB Ethernet gadget with one CDC NCM function (Windows 10 and later, macOS and Linux drive it with no extra driver; CDC ECM on a kernel without NCM). NetworkManager's shared mode runs dnsmasq and gives the computer an address. Without dnsmasq in the image, give the computer 10.55.0.2/24 by hand. ssh sst@10.55.0.1 reaches the unit once SSH is on.

Connected to a hub

The same gadget, but the unit asks for an address and keeps asking: with no cable in yet, with no host answering, after an unplug, after the host restarts. The page says it is waiting until a host answers. Its gadget MACs come from the unit's /etc/machine-id (host side 02:…, device side 06:…), the same every time and different on every unit, so several units on one hub never collide. Release images ship an empty machine-id, so each card makes its own at first boot.

As a host

The port is a USB host. A bridge, br-usb, takes in every USB Ethernet link that appears on it (drivers cdc_ether, cdc_ncm, rndis_host), including ones already plugged in when host mode starts, and hands out addresses. The page counts the links on the bridge as joined.

Any USB Ethernet joins, not only other units: a USB Ethernet adapter, a phone's USB tethering, or a unit left in "connected to my PC". While host mode is on, an adapter on this unit is part of the bridge, not a network of its own.

Remembering

Remember network settings is off until the user turns it on. While it is on, the mode in use comes back at boot: sndstation-usbnet.service (a oneshot after NetworkManager) runs sndstation-netctl usb-boot, which reads /etc/sndstation/usb-network and sets that mode. Changing mode while remembering updates it; turning it on while off remembers off. A remembered mode the unit can no longer do is left off, and the reason goes to the journal. Wi-Fi and SSH are not part of it: NetworkManager already keeps Wi-Fi networks, and SSH stays on through restarts on its own.

Which units can do which mode

  • The device modes (PC, hub) need a port with a device mode: a UDC under /sys/class/udc, or a USB role switch under /sys/class/usb_role that can make one, and the kernel's libcomposite.
  • Host mode needs a USB host controller with a port of its own beside the UDC's (H700 units have a separate host-only EHCI port), or a role switch.
  • One UDC takes one gadget. If another gadget already holds it (a boot service from outside sndstation, say), the device modes are not offered and the page says "The USB port is in use by another USB gadget (name)".

The page lists only what the unit can do, and says why for the rest.

Role switches (RK3326). The port is told to be a device for the device modes and a host for host mode, and put back as it was afterward. A device port is no host: a USB Wi-Fi or Ethernet adapter on it stops working, and the page says so. Host mode refuses on a role-switch port while another gadget holds it.

RK3326 cards need a device-tree overlay. The harvested RK3326 device trees (all but the GKD Pixel 2's) leave the USB PHY's OTG port disabled, so the device modes bind but nothing reaches the cable. The fix is an overlay that sets /syscon@ff2c0000/usb2phy@100/otg-port to okay, applied from the card's config.txt (overlays=). It belongs to the card image, not to this package.

Underneath

Everything runs through the root helper, as the launcher is never root:

sndstation-netctl usb-status                 the usb section of `status`, alone
sndstation-netctl usb-mode off|pc|hub|host   usb-on and usb-off are pc and off
sndstation-netctl usb-remember on|off
sndstation-netctl usb-boot                   the remembered mode, at boot

usb-status (and the usb section of status) says:

Key Meaning
supported, why the device modes, and why not
host, hostwhy host mode, and why not
mode off, pc, hub, host
active, ip on, and the unit's address (empty while a hub waits)
joined host mode: links on the bridge
remember yes or no
role=switch the port has a role switch

What it makes:

  • the gadget: configfs /sys/kernel/config/usb_gadget/sndstation
  • NetworkManager connections, all made with save no, so none outlives a restart: sndstation-usb (PC and hub), and for host mode the bridge sndstation-usbhost and its port profile sndstation-usbhost-port (match.driver, multi-connect multiple)
  • dnsmasq's drop-in /etc/NetworkManager/dnsmasq-shared.d/sndstation-usb.conf (dhcp-option=3, dhcp-option=6: no router, no DNS) in PC and host mode
  • /run/sndstation-usb-mode (the mode in use) and /run/sndstation-usb-role (a role switch's old role)
  • /etc/sndstation/usb-network while remembering, removed on purge

NetworkManager leaves USB gadget interfaces unmanaged (its udev rule expects whoever made the gadget to set it up). PC mode activates its connection explicitly. Hub mode also sets the device managed and makes its connection autoconnect, so it comes up whenever a host answers.

When it does not come up

  • Nothing on the host side at all (lsusb shows nothing, the hub's port reads not attached in /sys/bus/usb/devices/<hub>/<hub>-port*/state): the cable or the port, or, on RK3326, the overlay above.
  • The link is there but no address: ping every IPv6 node on it, ping -6 ff02::1%br-usb on the host, to see who is on it with no IPv4 at all, then ssh to the answer.
  • Who has joined, by name: ip link show master br-usb, and the leases in /var/lib/NetworkManager/dnsmasq-br-usb.leases.

Not done

  • Routing a hub's units out to the internet through the host (shared mode's NAT rules also need nftables expressions these kernels lack).
  • Showing an address on the page for a gadget the launcher did not make.
