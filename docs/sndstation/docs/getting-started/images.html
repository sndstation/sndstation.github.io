Getting an image, and going back

Draft for #168. Placeholders marked TODO(#236/#…) wait on a decision. #236 tracks each one, and the second number is the decision's closed issue.

A private-beta tester runs sndstation from an SD card image. This page says where the image for each unit comes from, how to put it on a card, and how to go back to the unit's stock firmware.

Where images come from

Images are built in sndstation/distribution, a private repository. How an invitee gets one (read access to that repository, or an image handed over) is TODO(#236/#124). Whether the repository later opens is TODO(#236/#120). Do not look for a public download: none is published.

Which image each unit runs

Each unit runs the sndstation rootfs, ROCKNIX or its stock image. The choice per unit is TODO(#236/#124). What the docs record:

The sndstation rootfs is a Debian system. Where one is not offered for a unit, you can install the platform onto a Debian or Ubuntu image the unit already runs: see Installation.

Before you flash: keep the stock card

Flashing overwrites the card. To be able to go back:

  • Keep the original card and flash a second one. This is the safest.
  • Or image the stock card first, with the card in a reader. On Linux, after finding the device as below:

sh sudo dd if=/dev/sdX of=stock-backup.img bs=4M status=progress

Keep stock-backup.img somewhere safe. It is as large as the card.

Whether any of the eight boots from internal storage rather than the card is TODO(#236/#124). This page assumes the card.

Flashing a card

Check the device name twice. dd writes to whatever it is told to, and a wrong name overwrites a disk you want. Look at the size and the label.

If you would rather not use a terminal, a graphical tool such as balenaEtcher writes an image to a card and checks it. Pick the image, pick the card, flash.

With dd:

# Linux: find the card; it is the one that matches your card's size
lsblk
sudo dd if=the-image.img of=/dev/sdX bs=4M conv=fsync status=progress

# macOS
diskutil list
diskutil unmountDisk /dev/diskN
sudo dd if=the-image.img of=/dev/rdiskN bs=4m

If the image is compressed, decompress it first. The image's format is TODO(#236/#124).

When it finishes, eject the card, put it in the unit and switch on. A working install boots to the launcher: see Installation, Verifying.

Going back to the stock firmware

Put the unit's original card back, or reflash the vendor's stock image onto a card:

  1. Get the stock image from the vendor's own firmware page for that model. Do not use a copy of unknown origin.
  2. Flash it as above, or write back your stock-backup.img.
  3. Boot. The unit is as it was.

This assumes the unit boots from the card. If it boots from internal storage, going back differs: TODO(#236/#124).

Slot 7 (RG35XX SP) needs a stock BSP image anyway, for the hallkey reading; keep it.

Problems

If a unit does not boot after flashing, reflash the card, and try a second card if it still fails. A hardware result, good or bad, goes to reporting.md. Known problems are in known-issues.md.
