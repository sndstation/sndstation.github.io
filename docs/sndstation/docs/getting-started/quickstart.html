Quickstart

Draft for #169.

This page is for people writing an app. To put sndstation on a unit and try it, start with Installation.

1. Run the launcher on a desktop

After building:

./build/sndstation

The keyboard stands in for the pad (arrows, Z/X, Return, Backspace). --fake-audio rk817 pretends to be a handheld's sound card.

2. Write an app

Start from examples/hello: a complete app in one file. It opens the screen, reads the pad, plays a sound and quits back to the launcher, and its README walks through it.

An app is an ordinary program. It is listed by the launcher when its package installs a manifest, /usr/share/sndstation/apps/<id>.json:

{ "name": "Example", "description": "What it is, in a line",
  "exec": ["/opt/example/example"], "order": 10 }

When the user picks it, the launcher shuts itself down and execs it, so the app has the display, the audio device and every byte of memory to itself. When it exits, the session brings the launcher back.

To use the SDK, add this tree to your build and link the library:

add_subdirectory(path/to/sndstation ${CMAKE_BINARY_DIR}/sndstation)
target_link_libraries(myapp PRIVATE sndstation::sndstation)

The SDK is a library, not a framework: your program owns its main loop and calls in. Its headers are included as <sndstation/…>, and <sndstation/sndstation.h> includes them all. Everything in them is in namespace sndstation (sndstation::pad, sndstation::gfx, sndstation::AudioOut, …); qualify it, or write using namespace sndstation; in your own files.

The headers are listed in the API reference.

The platform's settings are shared by every app on the unit: the gamepad database, stick calibration, and the unit's audio. For audio, that is where it plays, the routes, each output's volume and maximum, and the rate and buffer size. The launcher writes them; an app reads them through the SDK and keeps its own settings in ~/.config/<YourApp>.
