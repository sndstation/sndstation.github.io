From flashing a card to the launcher

For private-beta testers. You need a supported unit (supported.md) and an SD card.

  1. Get the image for your unit and keep the stock card or image it first: images.md.
  2. Flash the card and put it in the unit: images.md.
  3. Switch on. The unit boots into the launcher on its own screen: the install sets tty1 to log the user in and run sndstation-session (launcher.md, "Booting into it").
  4. Check it as in Verifying.
  5. On the first run, the launcher asks to map the pad if it does not know it, and to set up the sound by ear. Both can be skipped and done later from Controls and Audio.
  6. Report what you see, good or bad: reporting.md.

If the image already carries sndstation, you are done. If you started from a plain Debian or Ubuntu image, install the package as in Installing on a handheld. What the install does as root is listed in deb-root.md. Going back to the stock firmware is in images.md.

Whether a given image carries sndstation already is TODO(#236/#124).

Building from source

For developers.

The third-party libraries in third_party/ are git submodules, so clone with them, or fetch them into a checkout you already have (and again after a pull that moves one):

git clone --recurse-submodules <url>
git submodule update --init --recursive   # in an existing checkout

Debian or Ubuntu, on the handheld itself or a desktop:

sudo apt install build-essential cmake pkg-config libsdl2-dev libsdl2-ttf-dev libsdl2-image-dev libasound2-dev
cmake -S . -B build
cmake --build build -j4
./build/sndstation            # the launcher, in a 640x480 window on a desktop

Tested with SDL 2.0.20 (Ubuntu 22.04, the oldest it is built on) and SDL 2.30 (Ubuntu 24.04). alsa-lib (libasound2-dev, which libsdl2-dev pulls in anyway) gives the audio stream, the mixer, and MIDI their ALSA side; built without it, sound is SDL's and MIDI has no devices.

On macOS, for development: brew install pkg-config sdl2 sdl2_ttf sdl2_image, then the same cmake lines.

A desktop build is fully usable for development. The keyboard stands in for the gamepad (arrows, Z/X, Return, Backspace), and --fake-audio rk817 answers as a handheld's sound card. --fake-net gives SETTINGS → Network an in-memory unit: networks to join, Bluetooth devices to pair, and USB networking and SSH to turn on. ./build/sndstation --shots DIR writes every screen as a BMP without a display.

Tests, git hooks, and the pre-push checks are in CONTRIBUTING.

Installing on a handheld

A tagged release (v0.12.0, …) carries two packages for arm64 units, built on Ubuntu 22.04. They install on Ubuntu 22.04 and later and Debian bookworm and later. Releases up to 0.15.0 were built on Debian trixie and need trixie or later:

  • sndstation_<version>_arm64.deb, the platform;
  • sndstation-vendors_<version>_all.deb, the vendors a unit can trust.

How an invitee downloads them is TODO(#236/#120/#122). Copy both to the unit and install them together:

sudo apt install ./sndstation_*_arm64.deb ./sndstation-vendors_*_all.deb

To package a checkout instead, run packaging/make-deb.sh on the unit. It builds for the system it runs on and writes both packages to dist/:

packaging/make-deb.sh           # builds, then packages both into dist/
sudo apt install ./dist/sndstation_*.deb ./dist/sndstation-vendors_*.deb

The sndstation package recommends sndstation-vendors but does not need it. That package holds the vendors SETTINGS → Software packages offers to trust (updates.md, "Vendors"). Without it the launcher works, and that page lists no vendors.

On a recognized handheld the install also sets the unit up to boot into the launcher: - a realtime allowance for the audio thread; - a udev rule for the stick lights; - tty1 autologin into the session; - a sudo rule that lets SETTINGS → Network run its one network helper as root.

Anywhere else it changes nothing outside /usr/share/sndstation. docs/launcher.md has the details and the switches (SNDSTATION_BOOT=no, SNDSTATION_USER=…).

Verifying

A working install on a handheld:

  • It boots to the launcher on tty1, with no login prompt, showing the APPS page. L1 and R1 change the page: APPS, PLUGINS, SETTINGS, ABOUT.
  • ABOUT shows the unit. It lists the platform's version, the board, the SOC ID, the kernel, CPU, memory, SDL, the display, and the input device. The SOC ID is how the unit is told from another of its model (unit-identity.md).
  • The pad works. A unit whose pad is not in the gamepad database opens Controls on a first-run card. With no pad found at all the launcher says "No gamepad found" and leaves to a shell after five seconds.
  • Exit to shell ends the session and leaves a prompt. It is the last item of the power menu: press MENU (the unit's FN, Home, or MENU key), or hold SELECT and press START (launcher.md, "The power menu"). Logging out logs in again, and the launcher returns.

From a shell on the unit (ssh will do), after logging in again so that pam_limits has run:

dpkg -s sndstation | head -3   # the package is installed, and its version
groups                         # audio, video, input (and dialout for the stick lights)
ulimit -r                      # 95: the audio thread may run realtime

The install script says which user it set up and warns if that user is missing from audio, video or input (launcher.md, "Booting into it"). A realtime refusal is said on stderr and shown on AUDIO / DIAGNOSTICS, row Thread (rt-bench.md, "Allowing it").

On a unit with stick lights, sndstation --led-test lights the rings in turn (stick-leds.md).

On a desktop, ./build/sndstation opens a 640x480 window, and ctest --test-dir build runs the tests (CONTRIBUTING). Nothing else is installed, and nothing boots into it.

If something is wrong, see known-issues.md.
